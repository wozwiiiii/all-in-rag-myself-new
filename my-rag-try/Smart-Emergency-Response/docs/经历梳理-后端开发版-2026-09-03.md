### 简历表述（可直接粘贴）

- 基于 **FastAPI** 构建分层后端（api 装配 / orchestrator 编排 / rag+tabular 领域 / llm+core 基础设施四层），**LLM 调用统一收口**单一 client（chat/rerank/embed + 重试 + 缓存），业务模块禁止散落 SDK 调用
- 实现 **异步编排**：asyncio 意图路由 + hybrid 双路并行（`asyncio.gather` 容错版）、120s 总超时、单路失败/拒答降级不中断；核心接口约 240 行
- 构建 **统一异常体系**：7 类 `AppError` 子类映射 HTTP 状态码（401/429/502/504 等），未知异常 500 通用文案、堆栈只进日志不外泄
- 实现 **认证与限流**：`X-API-Key` 常数时间比较（防时序侧信道）+ 每 key 滑动窗口限流（deque 时间戳 + 线程锁，`Retry-After` 头）；探针 liveness/readiness 分离
- 落地 **可观测与并发安全**：结构化 JSON 日志（request_id 全链路贯穿）、**token usage 线程安全累加器**（规避 contextvar 在 ThreadPoolExecutor 并行抽取中的丢失问题）、SSE 流式接口；测试 **120 项全绿**

## 面试叙事建议（后端方向）

**该岗位最关心**：并发安全、降级可靠性、接口契约、可观测。四条都能落到具体代码：

1. **并发**：为什么 usage 用「实例级累加器 + Lock」而非 contextvar——因为 ThreadPoolExecutor 并行抽取会让 contextvar 写不回父上下文。能讲清这个取舍，比"我用了锁"高一个层级
2. **降级**：每层失败都有退路（BM25 失败→纯向量、rerank 失败→RRF、路由失败→启发式、hybrid 单路失败→幸存路），且**每层独立日志关键字**可事后审计
3. **契约**：`/qa` 同步 + `/qa/stream` SSE 双接口；SSE 响应开始后无法改状态码，异常以 error 事件收尾而非 500 截断
4. **可观测**：request_id 贯穿中间件→日志→响应头，一个请求的所有日志可一次捞出

**最有区分度的一句话**：*"路由是单点，必须永不抛异常——分类 LLM 挂了也要给出可用路由。"* 体现的是"把不可靠的 LLM 当成会失败的依赖来设计"的后端思维。

**避坑**：后端面试不必大谈"评测指标饱和"（那是算法/AI 方向的故事），聚焦并发、降级、契约、可观测；「120 项测试全绿」可强调其中沙箱安全测试的纵深防御设计。
