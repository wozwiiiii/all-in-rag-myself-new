## 批次 1：评测体系修复（P0，先修尺子）

**根因**：`eval/dataset.jsonl` 无 `reference`（0/18）→ `semantic_score` 恒返回 0.5
→ 0.3 语义权重完全失效，公式退化 `0.7×关键词命中 + 0.15`，单题上限 0.85。

**改动**
- `eval/dataset.jsonl`：18 题加 `expected_route`；16 题补人工 `reference`
  （基于向量库原文 chunk 撰写，先跑检索定位，非凭空编造）
- `eval/metrics.py`：`score_answer` 加 `expected_route` 参数，refuse 判定显式化（兼容旧隐式）
- `eval/run_eval.py`：改读新字段；refuse 以 `refused` 标志判定（`_route_correct`）
- 新增 `tests/test_metrics.py`（12 项）

**效果**：avg 0.8667→0.9647；**单题出现真实区分度**（0.93~0.976），天花板回到 1.0。
新信号：无满分题 → 生成与 reference cosine 非完全一致，是此前被 0.85 掩盖的真实差距。

## 批次 2：Token usage 可观测

**方案**：实例级线程安全累加器 + 请求级快照差值。
否决 contextvar——generator 用 ThreadPoolExecutor 并行抽取，contextvar 在池线程
copy-context 写不回父上下文会丢并行 token。

**改动**：`client.py`（累加器+`usage_snapshot/delta`+`llm_call_usage` 日志）、
`QAResult.usage`、`UsageMeta`、`routes.py` 回填。新增 `tests/test_client_usage.py`（5 项）。

**真实验证**：text 题 8 次调用 6000-8700 tokens，并行抽取不丢。

## 批次 3：输入侧注入防护

**做法**：结构隔离（`agent._select_tables` 拆 system/user）+ 输出侧 `check_prompt_leak` 检测。

**⚠️ 中途发现并修复的误伤问题**（这是本轮最有价值的判断点）：
首次将 `delete_status=0`/`check_status=2` 列入泄露特征，导致**全部 table/hybrid 题被误拦**
（avg 0.9647→0.5943）。原因：表格路 agent 会把业务 SQL 规则当**筛选依据**合法写进答案，
不是泄露。修复：签名只收"prompt 元层"特征（角色定义/协议标记/画像标题），不收
可合法出现在业务答案里的 SQL 规则。

**真实验证**：诱导表格路复述完整 system prompt → 被拦截替换为安全文案，
日志 `prompt_leak_detected`，零泄露。

## 批次 4：SSE 阶段事件流

**做法**：`answer()` 重构为消费 `_answer_stages()`（async generator），新增 `answer_stream()`；
`POST /qa/stream`。事件：routing→route→working(branches)→answer/error。

**两个设计判断**
- 分支是单次阻塞调用，无法细分检索/生成 → 统一发 working 阶段（如实标注粒度），
  不做破坏 client 收口惯例的全 token 流。
- SSE 响应开始后无法改状态码 → 路由层 catch 异常以 error 事件收尾，而非 500 截断。

**真实验证**：首事件 <1s，事件顺序正确，usage 随 answer 事件回传。

## 各批次未做项及理由（须能在复盘时复述）

- 正则 SafetyRuleValidator：黑名单不可穷尽 + 否定句假阳性会误伤正确答案
- 知识图谱/多租户/角色/反馈：无对应评测题/第二租户/真实用户，收益不可验证
- 全 token 流式：需 AsyncOpenAI 破坏 LLM 收口惯例，收益小于侵入

## 结论

四批次均落地并独立验证。核心收益不是"分涨了"，而是：
1. **尺子修好了**（语义权重生效、路由判定正确），后续一切优化可被可信度量；
2. **暴露了真实差距**（无满分题），指引下一轮 P1 正确性维度；
3. **guard 误伤的自证与修正**体现了"先修度量、再谈优化，改完用评测验证"的闭环。
