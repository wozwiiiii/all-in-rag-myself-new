## 项目经历 · 智能应急问答系统（RAG + 多 Agent 编排）· 独立开发

> 面向危化品应急管理场景的混合问答系统，核心是"知识在文档里走检索、知识在数据库里走代码"的 Agent 编排。

### 简历表述（可直接粘贴）

- 设计并实现 **混合 Agent 编排**：LLM 意图路由（text/table/hybrid 三分类 + 启发式降级）分发到 RAG 检索链与 Text-to-Pandas 表格 Agent 双链路，hybrid 双路异步并行后由 LLM 融合，单路失败/拒答均降级不中断
- 构建 **两阶段表格 Agent**：先由 LLM 选表（2-gram 启发式兜底、永不抛异常），再注入所选表 schema 画像进入 **ReAct 循环**（Thought/Action/Observation 文本协议 + 正则解析），沙箱执行失败的 traceback 回填下一轮实现自愈，最多 8 轮
- 实现 **RAG 三路融合检索**：向量 cosine + BM25（jieba 分词）+ rerank 精排，RRF 融合取优；诊断脚本证明"召回非瓶颈、失分在生成端"，避免无效优化
- 用 **评测闭环驱动迭代**：自建 18 题评测集，诊断出"评分指标语义权重失效"（`reference` 缺失致 0.3 权重恒 0.5、单题上限 0.85）并修复，天花板恢复至 1.0；两遍生成（逐 chunk 并行抽取 + 要点程序化拼接）使 text 关键词覆盖 90%→100%
- 设计 **prompt 注入防护**：输入侧结构隔离（选表消息拆 system/user）+ 输出侧特征检测；测试 120 项全绿，其中 30 条沙箱攻击载荷全部拦截

## 面试叙事建议（AI 应用 / Agent 方向）

**该岗位最关心三个问题**：你怎么让 Agent 可靠、你怎么评测 Agent、你怎么控制成本。三条都能用本项目实测回答：

1. **可靠**：「LLM 不可靠的地方用代码补」——两遍生成从"让 LLM 重组 30+ 要点"改为"代码程序化拼接、LLM 只写结论段"，关键词覆盖 90%→100% 且延迟反而下降
2. **评测**：「先让尺子可信再调系统」——发现 `reference` 缺失导致语义权重失效、单题撞 0.85 天花板，反推 `(16×0.85+2×1.0)/18=0.8667` 精确吻合，修复后才谈优化
3. **成本**：token usage 观测（实例级累加器）量化每次调用成本，为"抽取轮换小模型"提供决策依据

**最有区分度的一句话**：*"我没急着加特性，先证明自己的评测指标已经饱和了。"* ——这是自我证伪能力，比任何单项技术点都高一个层级。

**避坑**：不要孤立写"总分 0.96"，重点讲"发现语义权重失效 → 诊断 → 修复 → 重新验证"的闭环；也不要泛化说"做了 prompt 工程"，而要落到"文本协议 vs function calling 的实测选型"这个具体决策。
