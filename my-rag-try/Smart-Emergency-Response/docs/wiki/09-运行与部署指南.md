# 09 · 运行与部署指南

## 环境要求

- Python >= 3.10（实测 3.12）
- 建议项目级 venv（`.venv/`，已入 .gitignore）：避免污染全局 site-packages
- 数据：`advance/datas/` 下 20 篇法规文档 + 17 张 xlsx（随仓库）

## 安装

```bash
python -m venv .venv
.venv\Scripts\python.exe -m pip install -e ".[dev,ocr]"
```

- `dev`：pytest + httpx
- `ocr`（可选，约 300MB）：pypdfium2 + rapidocr-onnxruntime——扫描版 PDF 兜底；**不装则扫描页自动跳过并告警，不阻断构建**
- 主依赖：fastapi / chromadb / openai / tenacity / pandas / pyarrow / **rank-bm25 + jieba**（BM25 混合）

## 配置

```bash
cp .env.example .env    # 填 OPENAI_API_KEY（硅基流动等 OpenAI 兼容服务）
```

| 关键项 | 说明 |
|---|---|
| `OPENAI_API_KEY / BASE / MODEL` | LLM 接入；模型可随时切换（客户端无绑定） |
| `API_KEYS` | 业务接口认证（逗号分隔多 key；空=认证关闭仅本地） |
| `TOP_K / SCORE_THRESHOLD` | 检索条数与拒答阈值 |
| `RECALL_K / RERANK_ENABLED / BM25_ENABLED` | 混合检索开关（各有降级） |

## 完整运行序列

```bash
# 1. 构建索引（一次构建，服务端只读加载）
.venv\Scripts\python.exe -m scripts.build_index
# 输出：15 个文件，710 分块；.doc/.wps 跳过列表

# 2. 启动服务
.venv\Scripts\python.exe -m uvicorn app.main:app --host 0.0.0.0 --port 8000

# 3. 验证
curl http://127.0.0.1:8000/api/v1/health
curl http://127.0.0.1:8000/api/v1/ready
curl -X POST http://127.0.0.1:8000/api/v1/qa \
     -H "Content-Type: application/json" -H "X-API-Key: <key>" \
     -d '{"question": "涉及重氮化工艺的企业数量？"}'

# SSE 流式接口（首事件 <1s，逐阶段推送）
curl -N -X POST http://127.0.0.1:8000/api/v1/qa/stream \
     -H "Content-Type: application/json" -H "X-API-Key: <key>" \
     -d '{"question": "涉及重氮化工艺的企业数量？"}'
```

首次启动会做 Excel→parquet 预转换（最大表 26 万行约 100s）；后续启动幂等跳过（日志 `converted_now: 0`）。

## 测试与评测

```bash
# Windows 必须先关字节码写入（避免沙箱拦 .pyc）
$env:PYTHONDONTWRITEBYTECODE='1'
.venv\Scripts\python.exe -m pytest tests/ -q -p no:cacheprovider   # 120 项

.venv\Scripts\python.exe eval/run_eval.py            # 全量 18 题（~6 分钟）
.venv\Scripts\python.exe eval/run_eval.py --limit 5  # 冒烟
.venv\Scripts\python.exe eval/diag_retrieval.py      # 检索三路排名诊断
```

评测报告输出至 `eval/reports/report-<时间戳>.md`。**注意**：18 题单跑噪声 ±0.015，小于此的差异不可据此评测集分辨（README 已声明）。

## Docker 部署

```bash
cp .env.example .env && vim .env
docker compose up -d --build
docker compose exec qa python -m scripts.build_index   # 首次构建索引
```

镜像无状态（多阶段构建、非 root 用户），数据与构建产物挂载宿主机。

## 故障排查（日志关键字索引）

| 症状 | 日志关键字 | 含义/处置 |
|---|---|---|
| 启动报 config_error | `missing_openai_api_key` | .env 未配置 key |
| 问答报 503 | `向量索引不存在` | 先跑 `scripts.build_index` |
| 检索质量疑虑 | `retrieve`（candidates/bm25_used/rerank_failed） | 看三路状态与候选数 |
| BM25 未生效 | `bm25_failed_fallback_vector` | 依赖未装：`pip install rank-bm25 jieba` |
| 表格题反复失败 | `sandbox_violation` + `tabular_step ok=false` | LLM 代码违规/报错自愈中（最多 8 轮） |
| 表格超时 | `qa_timeout` | 自愈循环耗尽 120s；缩小问题范围 |
| 请求 429 | `rate_limited` | 限流触发，看 Retry-After 头 |
| OCR 未生效 | `ocr_deps_missing` | 装 `.[ocr]` extra |
| 索引构建跳过文档 | report.skipped 列表 | .doc/.wps 不支持（已知限制） |
| 成本排查 | `llm_call_usage`（含 model/token 数） | 每笔 LLM 调用的 token 用量；`qa_done` 的 usage 字段为单请求聚合 |
| 疑似提示词泄露 | `prompt_leak_detected` | 输出侧检测命中，答案已替换为安全文案 |

## 已知限制（如实）

- 限流单实例（多实例需 Redis）
- 沙箱子进程以当前用户权限运行（对抗高阶攻击者需 OS 级降权）
- 语料到 10^5+ 时需将全量内存检索切回 Chroma query + id 映射（见 retriever.py 头注释）
- 评测集仍 18 题（噪声 ±0.015），未达 60–100 题的扩量目标
- 正确性维度缺失：指标只测关键词覆盖、不测数值是否答对（Q15 曾因字段误选得 0.49）
