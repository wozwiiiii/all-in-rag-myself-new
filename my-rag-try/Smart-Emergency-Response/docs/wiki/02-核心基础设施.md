# 02 · 核心基础设施（app/core/）

三个文件，职责一句话：**配置集中校验（fail-fast）、日志带 request_id 全链路贯穿、异常统一映射 HTTP 错误体**。

## config.py — 集中式配置

`pydantic-settings` BaseSettings，`.env` 缺关键项时启动即失败（fail-fast，不等到运行时才炸）。

```python
# app/core/config.py
class Settings(BaseSettings):
    model_config = SettingsConfigDict(
        env_file=(PROJECT_ROOT / ".env"),
        env_file_encoding="utf-8",
        extra="ignore",   # .env 里的注释/无关变量不报错
    )
    openai_api_key: str = ""        # 启动时校验，见 main.py lifespan
    ...
```

关键设计：
- **PROJECT_ROOT** = `Path(__file__).resolve().parents[2]`——所有路径（数据/存储）锚定在项目根，不受 CWD 影响。这是踩坑后的修复：曾因从其他目录启动导致相对路径全错。
- **`get_settings()` 加 `@lru_cache`**——进程内单例，避免每请求重读 .env。

### 全部配置项（默认值即文档）

| 配置 | 默认 | 作用 |
|---|---|---|
| `openai_api_key / base / model / embedding_model` | — | LLM 接入（硅基流动等 OpenAI 兼容） |
| `api_keys` | "" | 多 key 逗号分隔轮换；空 = 认证关闭（仅本地） |
| `text_data_dir / table_data_dir` | advance/datas/... | 数据源 |
| `chroma_dir / parquet_dir / cache_dir` | storage/... | 构建产物（.gitignore 排除） |
| `top_k` | 6 | 最终进入 prompt 的 chunk 数 |
| `score_threshold` | 0.35 | 向量 cosine 拒答阈值 |
| `recall_k` | 20 | 每路召回窗口（向量/BM25 各取 top-20 后并集） |
| `rerank_enabled / rerank_model` | true / bge-reranker-v2-m3 | 精排开关与模型 |
| `bm25_enabled` | true | BM25 混合开关（依赖缺失自动降级） |
| `rate_limit_per_minute` | 20 | 每 key 滑动窗口 |
| `qa_total_timeout_s` | 120.0 | 单问题总超时 |
| `sandbox_timeout_s` | 30.0 | 沙箱执行超时 |
| `agent_max_iterations` | 8 | ReAct 迭代上限 |
| `llm_timeout_s / embed_batch_size` | 45.0 / 32 | LLM 调用参数 |

> 注意 `api_keys` 的两个派生 property：`api_key_list`（解析逗号）与 `auth_enabled`（非空即开认证）——认证行为由配置驱动而非代码分支。

## logging.py — 结构化日志 + request_id 贯穿

- `setup_logging()`：JSON formatter，每行带 `ts / level / logger / msg / request_id`
- `request_id_var`（contextvar）：中间件 set，日志 filter 注入，响应头回传——**一个请求的所有日志（路由/检索/沙箱/生成）可通过 request_id 一次捞出**

```python
# app/main.py add_request_context()：每请求生成/透传 X-Request-ID
rid = request.headers.get("X-Request-ID") or uuid.uuid4().hex[:12]
token = request_id_var.set(rid)
```

客户端可自带 request_id 实现链路追踪对接（日志关键字 `request_id: "e37d07434d35"`）。

## errors.py — 统一异常体系

```python
# app/core/errors.py
class AppError(Exception):
    code: str = "internal_error"
    http_status: int = 500
    def to_dict(self): return {"error": {"code": self.code, "message": self.message}}
```

7 个子类与 HTTP 映射：

| 异常 | code | HTTP | 触发场景 |
|---|---|---|---|
| `ConfigError` | config_error | 500 | 缺 API key 启动失败 |
| `AuthError` | unauthorized | 401 | X-API-Key 无效 |
| `RateLimitError` | rate_limited | 429 | 超滑动窗口（带 Retry-After 头） |
| `LLMError` | llm_unavailable | 502 | LLM 重试耗尽（上层多降级捕获） |
| `SandboxViolation` | sandbox_violation | 400 | 代码未过 AST 白名单 |
| `SandboxTimeout` | sandbox_timeout | 504 | 沙箱执行超时 |
| `RetrievalUnavailable` | retrieval_unavailable | 503 | 索引未构建 |

消费侧（`main.py register_error_handlers`）：`AppError` → 统一 JSON 体；**未知异常 → 500 通用文案，完整堆栈只写日志不外泄**。

一个细节：`RateLimitError` 动态挂 `retry_after` 属性，异常处理器转成 `Retry-After` HTTP 头——异常体不只是错误信息，还携带协议元数据。
