# 07 · 评测与可观测（eval/ + tests/）

## 7.1 评测体系设计

### 评测集（dataset.jsonl）

18 题 4 类，覆盖三路由 + 拒答：

| 类别 | 题数 | 考什么 |
|---|---|---|
| text | 8 | RAG 检索 + 生成（法规解读类） |
| table | 6 | 表格代理（统计类，业务过滤规则） |
| hybrid | 2 | 双路并行 + 融合 |
| refuse | 2 | **抗幻觉**（"法国巴黎的应急预案""如何做红烧肉"——明确拒答得 1 分，编造得 0 分） |

**字段补全（2026-09-03）**：此前 `dataset.jsonl` 只有 `id/category/question/keywords`，**缺 `reference`**——这导致语义权重失效（见下）。现已补 16 题人工 `reference`（基于向量库原文 chunk 撰写）+ 18 题 `expected_route`。

### 指标（metrics.py）

`score = 0.7 × 关键词命中率 + 0.3 × 语义相似度`（对齐竞赛公式；关键词均权为简化）。

**关键修正：别名词典**（2026-08-31 引入）：

```python
# metrics.py — 动因注释原文
# 字面匹配的假阴性——Q8"吊装作业如何分级管理"的准确答案为
# "按照吊物质量分为一级/二级/三级"，语义完整却不含"分级"字样，实测被判 0.5 分。
KEYWORD_ALIASES = {"分级": ["一级", "二级", "三级", "特级"]}
```

口径修正透明化：metrics.py 注释记录动因与日期，历史报告对比需注明口径。

**指标饱和修复（2026-09-03，重要）**：补 `reference` 前，`semantic_score` 对缺参考的题恒返回 0.5，0.3 语义权重**完全失效**，公式退化为 `0.7×关键词命中率 + 0.15`，单题上限 0.85 而非 1.0——R8 的 0.8667 其实是"16 题全部撞 0.85 天花板"。补 `reference` 后语义权重生效、天花板回到 1.0，单题出现真实区分度（0.93~0.976），总分进入 0.94~0.96 区间。

**refuse 判定显式化**：`score_answer` 新增 `expected_route` 参数；refuse 题不再走路由对比（router 永不输出 refuse），改以 `refused` 标志判定——此前 refuse 题路由正确率结构性恒 0，现已 2/2。

## 7.3 方法论（比数据更重要）

### 诊断驱动（diag_retrieval.py）

**优化前先证明瓶颈在哪**。诊断脚本逐题输出"全关键词 chunk 在三路中的排名"：

```
 id cat       vec  bm25   rrf  keywords
  2 text        3     1     1  特级,一级,二级    ← BM25 强（术语精确匹配）
  7 text        1     3     1  重大,隐患,判定     ← 向量强（语义）
```

2026-08-31 的诊断结论：所有 text 题全关键词 chunk 已在 top-5 内——**召回不是瓶颈，失分在生成端**。这个结论避免了在检索上做无效优化。

### 噪声意识

同配置重复跑（R5/R6）实测方差 ±0.015。**小于该阈值的配置间差异不可辩护**——rerank、BM25 对总分的影响均在噪声内，价值分别论证为"上下文精度"（2/6→5/6 关键词 chunk）与"专有名词鲁棒性"（两路互补证据）。

R8（两遍生成）+0.04 的提升**可辩护**：text 类关键词覆盖从 ~90% 提到 100% 是逐题可验证的结构性变化（每题 0.617→0.850），不是采样波动——判断"超噪声"的依据不是分数差本身，而是**分数差背后的机制是否确定**。

> 面试话术：大部分人说"我加了 X 提升了 Y 分"；这个项目能说"我先证明了 X 不是瓶颈，避免了无效优化；加了 Z 后总分变化在噪声内，但用诊断脚本证明了它在该场景的价值"——测量驱动 vs 直觉驱动。

### 正确性维度的暴露（2026-09-03，Q15 实证）

批次 4 后复跑，Q15（hybrid，一般风险企业数 + 区域划分）得 0.49：agent 误用 `risk_rating_code` 字段查"一般风险"（该字段无此语义、返回 0 家），正确字段是 `enterprise_promise.risk_grade=3`（107 家，上轮选对字段得 0.969）。这是 LLM 字段选择的真实波动，非代码回归。它实证了当前指标的盲区：**只测关键词覆盖、不测数值是否答对**——答错字段的错误数值也能拿到关键词分。下一轮最高优先级是事实一致性校验。

## 7.4 测试体系（120 项）

| 测试文件 | 项数 | 覆盖 |
|---|---|---|
| test_sandbox.py | 30+ | **攻击载荷全部拦截**（动态导入/dunder 逃逸/memmap/别名链/进程执行族）+ 合法分析通过 + 死循环超时 |
| test_api.py | 7 | API 合约（认证/限流/错误体/探针/usage 契约） |
| test_api_stream.py | 4 | SSE 流式（事件顺序/格式/鉴权/错误事件） |
| test_router.py | 5 | 意图路由降级 |
| test_chunking.py | 6 | 标题分块 / 超长切分 / OCR 兜底 + 依赖缺失降级 |
| test_retriever.py | 5 | 阈值语义 / BM25 并集 / rerank 重排与降级 / 开关 |
| test_generator.py | 9 | 双层拒答（60 字符限定）+ 两遍生成（逐 chunk 抽取 / 程序化拼接 / 重编号 / 部分失败容忍 / 全失败退化） |
| test_bm25.py | 6 | 分词检索 / 空防御 / RRF 融合语义 |
| test_metrics.py | 12 | keyword 命中/别名/中性分、refuse 显式判定、semantic cosine 数学正确性 |
| test_client_usage.py | 5 | usage 累加/快照/差值/并发计数不丢、pipeline 兼容无 usage 能力 stub |
| test_guard.py | 10 | 泄露特征命中/否定句不误伤/合法 SQL 规则不误判/pipeline 出口拦截 |
| test_pipeline.py / test_config.py | — | 编排降级 / 配置校验 |

> 注：pytest 权威计数为 **120 passed**（含 `@parametrize` 展开），与源码 `def test_` 数量（85）不同——沙箱 30 条攻击载荷、chunking 多格式等均通过 parametrize 展开。

Windows 注意：pytest 需 `$env:PYTHONDONTWRITEBYTECODE='1'`（避免沙箱拦 .pyc 写入）。
